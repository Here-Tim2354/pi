# TLDR

1. 仓库中的`.pi/extensions/`更名`.pi/extensions-src/`
2. 新Tool `fetch`，Jina实现的网页抓取。源码在更名后的拓展目录下`fetch.ts`
3. 新斜杠命令 `/limit-opencode`，采用官方余额查询API实现。同样放在拓展目录下`limit-opencode.ts`
4. `sync-global-pi.mjs`允许`npm run sync`同步本地仓库的`extensions-src`到全局`extensions`
5. 各种模型和Key的配置

## 1-更名

**背景**：之所以要这么做，是因为pi会同时发现全局和项目的extensions。使用自定义同步脚本`npm run sync`之后会导致全局和本地仓库同时拥有重复的文件，进而导致预期外的行为，比如重复注册Tool导致无法启动。

出于实验性质的目的，我会在项目中的extension做很多改动。短期内我不打算修改内核代码，采用这种接口的形式来低耦合实现功能。

**决策**：于是我采用更名的形式，让`extensions-src`能够被git管理的同时，全局pi享受本地仓库的自定义实现。


## 2-fetchTool

**背景**：Pi没有专门的获取网页的工具。由于我的电脑常驻TUN模式，Agent若要走`bash curl`，很容易碰到FakeIP拦截问题。

**决策**：虽然我可以配置来放行，但考虑到社区有成熟方案[Jina](https://jina.ai/reader/)，于是就自定义实现了一个Tool。

**设计**：可选mode来指定抓取网页的格式（markdown/txt/html），并且做了SSRF防护，错误处理和阶段（上限100KB）

## 3-limit-opencode

**背景**：Opencode前不久正式官方支持了通过API的形式来查询Go/Zen计划的余额。本人是Go计划订阅者，调查社区后发现许多包暂未对这一特性提供支持，走的仍然是读取Cookie爬取浏览器的链路。

**决策**：自定义实现了一个查询命令的方式。通过斜杠命令唤起查询API，然后返回Pi风格的字符行，并渲染到对话记录中。

## 4-同步

配合1而同步修改`npm run sync`脚本。
