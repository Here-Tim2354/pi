
# TLDR

1. `limit-opencode.ts`不再进入模型上下文
2. 新增`check-model.ts`功能可供查询模型连通性

# 1-oc限额不进入上下文

**背景**：发现模型能够读到我的Opencode限额，这是预期外的行为。不应当这么做。
**决策**：将旧的实现`pi.sendMessage()`切换成`pi.appendEntry()`，不会进入上下文的同时同样进入TUI渲染。

# 2-check-model.ts

**背景**：发现我总是切换到中转站的时候，模型不一定可用，但是我消息已经发出去了才能知道。故我总是频繁用`/tree`来回退到指定的消息。很烦。

**决策**：新增一个`check-model.ts`，专门用于检查当前已经配置的模型的连通性，绿色代表正常连通，红色代表错误或者超时。

**设计**：采用类似`/model`的TUI菜单界面，通过Tab键允许切换不同的`scope`来指定`scoped/custom/all`的模型，便于查看。

最初设计了可以传参数`/check-model scoped/custom/all/on`来直接指定范围/是否允许将内容注入到模型上下文。并且最开始设计中，TUI渲染的方式为通过颜色区分，而实际发送给LLM的则是格式化后的JSON来将传达信息。

后来一些事情（见插曲），仅保留了`on`参数，仅菜单通过多个按键操控足矣。

后续加入了更多体验优化：像`/model`那样通过上下方向键来滚动窗口，并发检测，`ctrl+o`展开面板。

**插曲**：中间我发现`/che...`通过Tab键补全之后，不能直接显示进一步参数。要求Pi修改时发现其修改了内核代码`packages/tui/src/components/editor.ts`。我对此感到惊讶，查询后得知社区早已推送了这个PR，核心维护者一开始接受，后来移出。原因这样改动会导致`Enter`键的语义发生冲突，破坏空参Enter打开对话框的语义。

后来我决定不修改内核代码，也去除菜单页面可选参数。仅保留有实用功能的on。
